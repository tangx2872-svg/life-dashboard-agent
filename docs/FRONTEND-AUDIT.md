# 前端审计与改造记录

审计日期：2026-10-29。实施前基线：59693c4。

## 现有系统

- 技术：原生 JavaScript 全局函数、静态 HTML/CSS；Node HTTP 服务、MySQL JSON 状态文档。无 Vue/React，也无编译构建步骤。
- 页面：首页、事项列表/详情、时间轴、Inbox、Ideas、历史、学习路线/阶段任务、实验/步骤、GPT 导入、数据管理、助手、提醒。
- 路由：原来只有 page/selectedProject 等内存变量，刷新丢失位置；多个脚本包装 render 并追加导航。
- 数据：Project 内嵌阶段/笔记；普通 Task 独立关联 projectId/phaseId；Roadmap 内嵌阶段/任务/学习笔记；另有事件、想法、收件箱、历史、实验、提醒、决策、导入批次、首页排序。
- API：GET/PUT /api/state（版本与 requestId、CSRF）；backup/snapshots；AI health/capture/text；旧助手接口。状态写入经 runDatabaseCommand 等待事务成功才反馈，冲突时回滚并要求重连。
- AI 正式接口返回 type/start_datetime 等字段，旧导入协议使用 kind/op。必须转换并预览，不可直接混用。

## 问题

1. 首页同时展示当前学习任务、路线、事项、今日任务，内容重复，缺少主行动。
2. 导航由多个脚本追加，入口过多；导出/导入和助手入口多处重复。
3. 卡片、按钮、标题、留白缺乏统一密度；长记录和宽操作区在窄屏挤压。
4. 缺少独立任务工作台、完成恢复、优先级、描述和日期统一编辑。
5. 无持久路由、全局命令入口、周回顾。
6. 网络错误与状态显示分散；旧删除/恢复流程仍使用原生 confirm。
7. 数据安全基础可复用：备份包含完整状态，事务、版本冲突、快照和导入批次机制应保留。

## 实施边界

新产品展示层复用旧业务操作和验证器；不迁移/清空数据库。旧页面保留在分组入口内。新字段按需追加，旧字段不删除。AI 先解析、编辑预览、用户确认，之后才统一保存。生产 AI 不使用 debug 降级，也不虚构结果。测试使用独立随机测试数据库，禁止操作用户数据库。

## 验收

覆盖导航刷新/后退、任务 CRUD/恢复/子任务、项目关联、AI 成功/失败/重复确认、数据库保存失败回滚；桌面与手机检查。完整备份、旧导入、实验、路线、提醒依旧保留。结果与已知限制在 FRONTEND-RESULTS.md 记录。

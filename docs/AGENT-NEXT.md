# 下一步接 Agent：先做实验模块

本次完成的是能独立运行、由 MySQL 保存的系统底座，没有假装已经接通 AI。

1. 在实验详情增加文字输入区。
2. 后端读取用户选中的实验和 revision，按需交给模型；不要发送全部私人数据。
3. 模型返回回答、澄清问题或 `life-dashboard.capture` v2 草案。
4. 沿用 `gpt-import.js` 的规范与 `experiments.js` 的准确 ID / expectedTitle 检查；模型输出不是可信命令。
5. 页面展示新增、修改、删除内容，用户明确确认后提交。
6. 提交时检查最新版本，冲突则重新读取，不覆盖新内容。后端也须校验操作范围，不能只依赖前端。
7. 文字流程稳定后再加录音转文字，复用同一条链路。

优先做好：读已有记录、不编实验结果、保留补充原文、正确定位对象、取消不保存、失败不冒充成功。

未来模型密钥只放服务端环境变量，不进入 public、仓库或导出备份。如果继续参赛，需要结合届时比赛要求确定 openJiuwen 的具体接入方式。

建议开发任务：
- A：选择演示场景与验收要求。
- B：实验对话输入及变更确认页面。
- C：Agent 提示词、工具读取和草案生成。
- D：模型调用接口、密钥及超时错误处理。
- E：误改、取消、并发、重试等案例验证与录屏。

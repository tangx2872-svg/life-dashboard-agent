# Life Dashboard 独立本地版

这是现有控制台的独立导出项目：**原来的页面与业务功能 + Node.js 后端 + MySQL 保存**。

网页不再把业务数据写进浏览器。重新打开浏览器、换一个浏览器，连接同一个本地服务就能读取 MySQL 中的内容。关闭服务不会删除数据库，但页面需要后端和 MySQL 都启动后才能使用。

## 先运行起来

需要 Node.js 22 或更新版本、MySQL 8.0 或更新版本。

### 方式一：Windows 本机快速启动

如果 MySQL 安装在 `C:/Program Files/MySQL/MySQL Server 8.0`：

1. 解压项目到一个固定目录。
2. 双击 `start-local.cmd`，首次启动需要联网安装依赖。
3. 保留启动窗口，在浏览器打开 **http://127.0.0.1:3000**。

脚本为本项目单独启动 MySQL，端口 **33316**。数据文件放在 `.local/mysql-data/`，不会使用、修改或关闭原有的 3306 实例。新数据库初始为空，没有带入作者个人数据。

本项目实际保存了数据以后，不要删除 `.local`。移动项目之前先导出完整备份；独立 MySQL 的路径记录在 `.local/mysql-local.json`，移动目录后建议按方式二连接已有数据库，或在新目录创建实例后导入备份。

如安装位置不同，在终端设置 `MYSQLD_PATH` 为你自己的 `mysqld.exe` 路径，再运行 `node scripts/local-mysql.mjs`。

### 方式二：使用你已有的 MySQL

1. 用管理员账号执行 `docs/mysql-setup.sql`，先替换示例密码。
2. 复制 `.env.example` 为 `.env`，填写数据库地址、端口、账号和密码。
3. 在项目目录运行：

```sh
npm install
npm start
```

默认打开 http://127.0.0.1:3000。使用已有数据库时，不运行独立 MySQL 初始化脚本。

项目附带 `pnpm-lock.yaml`；希望完全按锁定版本安装，可使用 `pnpm install --frozen-lockfile`。开发验收使用 Node.js 24、MySQL 8.0 和该锁文件。

## 把旧网站的数据搬过来

**代码包不包含你浏览器里的个人数据。** 旧网站的数据仍保留在原浏览器中。

1. 打开旧网站的「数据管理」。
2. 点「导出完整备份」，下载 JSON。不要用「复制给 GPT」代替。
3. 打开独立版，点「从旧站备份恢复」。
4. 查看恢复摘要，确认后整体恢复到 MySQL。
5. 检查项目、阶段、任务、子任务勾选、笔记、实验和顺序。

这是整体恢复，不是追加导入。数据库会在修改前保存旧状态，可通过「下载操作前快照」取回。损坏的 JSON 会被拒绝，旧状态不会被覆盖。

## 保存与备份

- 显示「已保存到 MySQL」后，才表示数据库已确认保存。
- 保存中请等待；关闭浏览器前应确认保存完成。
- 每次实际更改，数据库自动保留修改前的完整状态，最近 30 次。
- 「导出完整备份」直接从数据库下载，与页面当前临时草稿分开。
- 两个页面同时编辑时，过期页面不能覆盖新版本，会提示刷新重新操作。
- 网络中断、超时或数据库故障时，不会偷偷退回浏览器保存。请刷新读取数据库最新状态，避免重复操作。
- 数据库里的快照与主数据在同一台机器，不能代替异机备份。重要时另下载 JSON 保存。

默认只监听本机 `127.0.0.1`。这是单人本地项目，没有多人账号和数据隔离，不能直接开放到公网给多人使用。

## 文件怎么分

| 目录 / 文件 | 用途 |
| --- | --- |
| `public/` | 保留原有外观和业务功能的网页，加入数据库保存适配 |
| `original-site/` | 第 14 版线上网站原始文件，未改动的导出参考副本 |
| `server/` | Node.js 接口、MySQL 事务保存、历史快照和数据校验 |
| `scripts/local-mysql.mjs` | 可选的 Windows 独立 MySQL 启动 / 停止助手 |
| `tests/` | 真实数据库和浏览器验证，不使用个人数据 |
| `docs/` | 架构、Agent 后续计划、MySQL 初始化示例、测试结果 |
| `.env` | 你自己的数据库配置，不提交 Git，也不放进分享压缩包 |
| `.local/` | 你的独立数据库文件和运行配置，不提交 Git |

## 本次保留与改变

保留长期事项、学习路线、任务进度、时间轴、实验、想法、记录、JSON v2 导入、预览确认、完整备份恢复等业务逻辑。

主要改变：新增后端；以 MySQL 为数据来源；取消业务数据的 localStorage / IndexedDB 保存和浏览器文件权限依赖。空数据库不自动注入示例事项。独立版从数据库恢复数据，原站点不变。

MySQL 中先保存整份原有数据文档，另有版本、请求和快照表。**没有强行把项目、阶段、任务拆成一整套新表**，目的是减少迁移风险，保留现有字段和数组顺序。当前适合单人、小规模数据，不是高并发多人系统。

## Agent 做到哪里了

这次已做好后端保存与读取入口，保留了现有 JSON v2 增删改和预览确认。还提供实验目录和单实验读取接口，方便下一步接 Agent。

**本次没有接入模型 API，也没有宣称实现 Agent。** 不需要填写 AI 密钥；原有浏览器语音功能仍取决于浏览器支持。后续按 `docs/AGENT-NEXT.md` 增加自然语言到修改草案，再接现有确认保存即可。

## 准备上传仓库

当前只准备本地项目，没有创建或上传远程仓库。

`.gitignore` 已忽略 `.env`、`.local`、依赖、日志、备份和压缩包。上传前运行 `git status --short`，确认没有个人备份或密钥。可以保留 `original-site/` 作为迁移依据。

```sh
git init
git add .
git commit -m "Export Life Dashboard with MySQL persistence"
# 再到你自己的仓库平台创建空仓库，按平台提示添加 remote 并 push。
```

## 测试与停止

`npm test` 使用本项目独立 MySQL 配置，自动创建并清理独立的 `life_dashboard_test_*` 数据库，绝不清空业务库。使用已有 MySQL 的方式二时，测试前应另行准备隔离环境，不能直接拿个人库做测试。

浏览器测试额外需要 Playwright 和 Chrome；配置 `BROWSER_MODULE` 为 Playwright 模块入口路径后运行测试。没有配置时，该项明确跳过；数据库测试仍执行。详情见 `docs/TEST-RESULTS.md`。

关闭启动窗口可停止 Node.js。独立 MySQL 可用 `npm run stop:mysql` 停止；再次运行启动脚本会重新连接原数据。不要手动删除数据库文件来“重启”。
